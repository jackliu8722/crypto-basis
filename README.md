# crypto-basis

手工录入每一笔 USDT 计价的现货交易，自动算出每个币的**持仓成本**、**当前市值**和**收益率**。

定位是个人快速记账：数字够准、账能对上，不追求会计级的精确度。所有数据存在本机一个 SQLite 文件里，不上传任何地方。

---

## 快速开始

```bash
git clone <仓库地址>
cd crypto-basis
npm install          # 装根目录依赖
./start.command      # 一键启动
```

也可以双击 `start.command`（macOS）。启动后自动打开 **http://127.0.0.1:3001**。

首次启动会自动安装前后端依赖并构建前端，之后只在源码有变动时才重新构建。

### 启动参数

```bash
./start.command                                  # 默认端口 3001
./start.command --proxy http://127.0.0.1:7890    # 指定行情代理
./start.command --no-proxy                       # 不用代理
./start.command --port 8080                      # 换端口
./start.command --no-open                        # 不自动打开浏览器
```

等价的 npm 命令：`npm start`。

## 怎么用

### 记一笔

点右上角 **「+ 记一笔」**，弹窗里每个字段一行：

| 字段 | 说明 |
|---|---|
| 类型 | 买入 / 卖出 / 入金 / 出金 |
| 币种 | 自动转大写，如 BTC |
| 数量 | 买卖时必填 |
| USDT 金额 | 这笔涉及的 USDT 总额 |
| 时间 | 默认现在，可改成历史时间 |
| 备注 | 可选 |

填了数量和金额会自动算出单价，方便核对有没有填反。选「入金 / 出金」时币种和数量会自动隐藏。

**不记录手续费**——这是刻意简化的，定位是大概记录。

### 看数据

- **顶部卡片**：净资产、总收益率、USDT 余额、持仓市值、浮动盈亏、已实现盈亏、总投入本金
- **持仓表**：每个币的数量、均价、现价、市值、浮盈、收益率、占比；底部一行「USDT 现金」，占比加起来正好 100%
- **流水表**：所有交易，可按币种筛选
- **收益走势**：近 7 天 / 近 30 天 / 全部 / 自定义区间，见下方章节

### 删一笔

流水表每行右侧「删除」，点了会**整行变黄**并出现「确认删除？[确认] [取消]」，确认才真删。

删完顶部还有一条「已删除… [撤销]」提示——后端是软删除，撤销能完整恢复。所以误删有两道保险。

## 成本怎么算的

只存交易流水，每次打开页面时从零重放一遍。所以删一笔、补录一笔旧的，所有数字自动回到正确状态，不存在算错的历史残留。

### 规则

**买入**：USDT 减少，持仓数量增加，成本增加，均价重算

```
均价 = 总成本 ÷ 总数量
```

**卖出**：USDT 增加，按当前均价扣减成本，**剩余持仓的均价不变**

```
已实现盈亏 += 卖出所得 − 均价 × 卖出数量
```

**入金 / 出金**：只影响 USDT 余额和「总投入本金」，不影响持仓

### 口径说明（重要）

卖出后剩余持仓的成本价**不会**下降。举例：

| 操作 | 数量 | 均价 | 已实现盈亏 |
|---|---|---|---|
| 买 1 BTC，花 60000 | 1 | 60000 | 0 |
| 再买 1 BTC，花 80000 | 2 | 70000 | 0 |
| 卖 0.5 BTC，得 45000 | 1.5 | **70000（不变）** | +10000 |

有些 App 会显示成"卖完后成本价降到 60000"，那是另一种口径（成本 = 总买入 − 总卖出）。两种**总收益完全一样**，只是浮盈和已实现的切分不同。本工具采用标准口径，保证收益率公式在任何情况下都有效（另一种口径超额回本后成本价会变负数，收益率就没法算了）。

### 边界行为

- **卖出数量超过持仓**：直接拒绝，提示"当前仅持有 X"。新增交易时不会让你录出错的账
- **买入导致 USDT 余额为负**：允许保存，但余额标红并提示"可能漏记入金"。因为初始本金可能没填准，硬拦反而碍事
- **补录历史交易**：按交易时间排序重放，所以先录 10/28 的卖单、后补录 10/01 的买单也不会算错。注意补录前查询会因为"卖出超持仓"被拒绝，这是正常的
- **已清仓的币**：默认隐藏，勾「显示已清仓」可看到，已实现盈亏始终保留

## 收益走势与回撤

选「近 7 天 / 近 30 天 / 全部 / 自定义区间」，图上：

| 元素 | 含义 |
|---|---|
| 蓝色实线 | 总资产（USDT） |
| 灰色虚线 | 投入本金（初始本金 + 累计入金 − 出金） |
| 红色区块 | 最大回撤区间 |
| 悬停 | 查看任意一天的总资产、投入、收益、回撤 |

指标卡：区间收益、区间收益率、最大回撤、当前回撤、期末总资产。

### 口径

收益率和回撤都用**时间加权收益率（TWR）**计算，入金 / 出金会被剔除。举个例子：本金 1 万，某天转入 10 万，总资产变成 11 万——如果按净值算会显示"收益 1000%"，实际一分没赚。TWR 会把那 10 万当作外部现金流扣掉，收益率仍是 0。

图上同时画投入本金曲线，两条线的**间距**才是真实收益，入金只会让两条线一起上移。

### 历史价格

- 首次查看某区间时从 CoinGecko 抓日线，存进 `price_history` 表
- 之后直接读库，**不再发请求**；隔一个月再打开只会补缺口，不要求服务常驻
- 取不到历史价的日期用**成本价兜底**，图上会标注"该日缺价格，按成本估算"
- 免费接口上限约 365 天、日线粒度（日内涨跌看不到）

## 行情价格

现价从 CoinGecko 免费接口取，优先级：

1. 你手动填的价格（设置面板可覆盖任意币种）
2. 5 分钟内的缓存
3. CoinGecko 实时请求
4. 请求失败 → 沿用上次价格并标灰"已过期"
5. 连缓存都没有 → 显示 `—`

一次批量请求所有持仓币种，不会触发限流。USDT 按 1:1 计算，不算持仓。

**国内网络基本必须配代理**：CoinGecko 等行情源通常无法直连，在设置面板填 `http://127.0.0.1:7890`（按你的客户端口改），或用 `--proxy` 参数启动。不配也能用，只是取不到价，届时手动填价即可。

## 数据与备份

```
data/
  ledger.db              主数据库（所有交易、设置、价格缓存）
  backups/               启动时自动快照，保留最近 7 份
  coingecko-coins.json   币种映射缓存，每天更新
```

`data/` 已在 `.gitignore` 中，**不会进版本库**——账目数据不该提交到 git。

### 备份

```bash
npm run snapshot     # 生成一致性快照到 data/backups/，服务不用停
```

### 迁移到另一台机器

```bash
# 机器 A
npm run snapshot          # 或 Ctrl+C 停服后直接拷 data/ledger.db

# 拷到机器 B 的 data/ledger.db，然后
npm install && ./start.command
```

**注意**：服务运行时不要直接拷 `ledger.db`。数据库是 WAL 模式，未合并的数据在 `ledger.db-wal` 里，只拷主文件会丢数据。用 `npm run snapshot`、先 Ctrl+C 停服、或拷整个 `data/` 目录都没这个问题。

迁移后记得检查设置里的**代理地址**，端口可能因机器而异。

### 导出

设置面板底部有「导出 CSV」「导出 JSON」，或直接访问 `/api/export?format=csv`。

**目前只有导出，没有导入**——JSON 导出只能当备份查看，无法回填。跨机器迁移请用上面的拷文件方式。

## 命令速查

| 命令 | 作用 |
|---|---|
| `./start.command` / `npm start` | 单进程启动（推荐日常使用） |
| `npm run dev` | 双进程开发模式，前端热更新 |
| `npm test` | 跑后端测试（22 个：11 引擎 + 4 API + 7 走势） |

| `npm run build` | 只构建前端 |

日常用单进程就够了，`npm run dev` 只在频繁改界面时用。

## 当前不支持

以下都是刻意不做，不是遗漏：

- 合约、杠杆、永续、期权
- 手续费
- 资产转入（账户里原有的币）—— 只支持从 USDT 买起
- 非 USDT 计价的交易对
- 多账户 / 多交易所
- FIFO 批次成本核算
- 修改已录入的交易（要改就删了重录）
- 导入 JSON / CSV
- 分钟级走势与 K 线（只有日线）

服务只监听 `127.0.0.1`，局域网内其他设备访问不到——账目数据不应暴露到网络上。
